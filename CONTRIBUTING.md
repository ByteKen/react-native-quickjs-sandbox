# Contributing to react-native-quickjs-sandbox

Thank you for your interest in contributing to `react-native-quickjs-sandbox`! We welcome all contributions, from bug fixes and documentation updates to new features and performance enhancements.

This document outlines the guidelines and development workflow to make the contribution process smooth and effective.

---

## Code of Conduct

Please be respectful, professional, and collaborative in all communications, issues, and pull requests.

## Getting Started

### Prerequisites

To develop on the native modules, you will need:
- **Node.js**: >= 22.11.0 (recommended)
- **Android Development**: Android Studio, SDK, and NDK (version specified in `android/build.gradle` or matching your local setup).
- **iOS Development** (macOS only): Xcode and CocoaPods.

### Development Setup

1. **Fork and Clone the Repository**
   ```bash
   git clone https://github.com/ByteKen/react-native-quickjs-sandbox.git
   cd react-native-quickjs-sandbox
   ```

2. **Install Dependencies**
   ```bash
   npm install
   ```

3. **Build TypeScript**
   Ensure that typescript compiles successfully before testing:
   ```bash
   npm run build
   ```

---

## Development Workflow

### Project Structure

- `src/`: TypeScript source code (public JS/TS API and TurboModule specs).
- `lib/`: Compiled JS/TS output (auto-generated by `npm run build`).
- `cpp/`: C++ QuickJS engine integration and JSI bindings.
  - `cpp/quickjs/`: Included QuickJS source engine files.
- `android/`: Android native module (Kotlin wrappers and C++ linking).
- `ios/`: iOS native module (Objective-C++ and Podspec).

### Making Changes

1. **Branch Naming**: Use clear branch names like `feature/your-feature-name` or `bugfix/issue-description`.
2. **Code Quality**:
   - Write clean, type-safe TypeScript.
   - Keep C++ JSI code leak-free. Manage `JSValue` reference counts with RAII.
   - Document any public API changes.

---

## Submitting a Pull Request

1. **Verify your changes**: Ensure typescript compiles and tests run clean:
   ```bash
   npm run build
   ```
2. **Commit with clear messages**: Follow standard commit naming conventions (e.g., `feat: add console.log redirection`, `fix: resolve runtime JSI memory leak`).
3. **Open a PR**: Fill out the Pull Request template completely, providing steps to verify the changes and background context.

---

## Questions & Support

If you have questions, feel free to open a GitHub Discussion or submit a bug report via GitHub Issues. Thank you for contributing!
